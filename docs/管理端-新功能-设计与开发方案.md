> 版本：v1.0

> 适用范围：`frontend-pc`（管理端，3000）+ `backend`（8080）
> 关联文档：[功能设计报告.md](./功能设计报告.md)、[后端模块补全开发方案.md](./后端模块补全开发方案.md)

## 1. 背景与目标

### 1.1 背景

系统现有培训流程为「培训计划 → 任务下发 → 在线学习 → 在线考试」，但存在三处能力缺口：

1. **培训需求**无线上入口：各部门提出培训需求仍依赖线下沟通，需求无登记、无台账、无审批留痕，`tr_training_demand` 表已建但无任何实现。
2. **PDF 课件**缺独立管理：课程资料（`tr_course_file`）虽支持 PDF 上传，但 PDF 课件是教学主载体，需要「启用/停用、独立于普通资料之外组织、可作为课程详情页的重点展示对象」的专门管理，`tr_course_pdf` 表已建但无任何实现。
3. **培训计划审批后无落地动作**：计划「审批通过」仅把状态置为 `已通过(2)`，不生成任何任务、不发任何通知，审批通过的培训计划对学员端零影响，计划形同虚设。

### 1.2 目标

1. 新增**培训需求管理**模块：部门在线提需求，管理员登记/采纳/驳回，形成可追溯的需求台账。
2. 新增**PDF 课件管理**模块：课程下 PDF 课件的上传、列表、预览、启用/停用、删除。
3. **补全培训计划审批闭环**：审批通过后一键下发培训任务到目标岗位学员，并推送站内信通知；补齐计划状态 `已发布(4)` 的真实业务语义。

### 1.3 总览

| # | 模块 | 表 | 后端新增 | 前端新增 |
|---|------|-----|---------|---------|
| 1 | 培训需求管理 | `tr_training_demand`（已建） | 1 实体 + 1 Mapper + 1 Service + 1 Controller（6 接口） | 1 页面 |
| 2 | PDF 课件管理 | `tr_course_pdf`（已建） | 1 实体 + 1 Mapper + 1 Service + 1 Controller（5 接口） | 1 页面 |
| 3 | 培训计划审批闭环 | `tr_training_plan`、`tr_plan_course`、`tr_training_task`、`sys_message` | 修改 2 处现有 Service | 修改 1 页面 |

## 2. 培训需求管理

### 2.1 业务规则

- **提出部门**：需求由部门提出，`department_id` 记录申请部门（管理端由操作人选择）。
- **状态流转**：`0-待处理 → 1-已采纳 / 2-已拒绝`，采纳时需填写「采纳备注」，拒绝时必须填写「拒绝原因」。
- **采纳联动（可选增强）**：采纳需求后可一键「生成培训计划草稿」，把需求标题/培训主题/培训对象带入计划表单。
- **删除约束**：仅 `待处理(0)` 状态允许删除；已处理的需求保留审计留痕。

### 2.2 表结构（现状）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint PK | 主键 |
| `title` | varchar(200) | 需求标题 |
| `content` | text | 需求内容 |
| `training_topic` | varchar(200) | 培训主题 |
| `training_target` | varchar(500) | 培训对象 |
| `reason` | varchar(1000) | 需求原因 |
| `department_id` | bigint | 申请部门 ID |
| `status` | tinyint | 0-待处理 1-已采纳 2-已拒绝 |
| `create_time` / `update_time` | datetime | 时间戳 |
| `create_by` / `update_by` | varchar(50) | 操作人 |
| `deleted` | tinyint | 逻辑删除 |

> 表已存在，**无需执行 SQL**；「采纳备注/拒绝原因」沿用 `reason` 字段存储，避免加列。

### 2.3 接口契约（`/training/demands`）

| # | 方法 | 路径 | 说明 | 权限 |
|---|------|------|------|------|
| 1 | GET | `/training/demands` | 分页查询（关键字/状态/部门过滤） | TRAINING |
| 2 | GET | `/training/demands/{id}` | 需求详情（编辑回显用） | TRAINING |
| 3 | POST | `/training/demands` | 新增需求 | TRAINING |
| 4 | PUT | `/training/demands/{id}` | 编辑需求（仅待处理） | TRAINING |
| 5 | POST | `/training/demands/{id}/handle` | 处理需求（采纳/拒绝，带意见） | TRAINING |
| 6 | DELETE | `/training/demands/{id}` | 删除需求（仅待处理） | TRAINING |

**关键参数（POST / PUT）**：`title*`、`content`、`trainingTopic`、`trainingTarget`、`reason`、`departmentId`。

**关键参数（POST /{id}/handle）**：`status*`（1-采纳 2-拒绝）、`opinion`（采纳备注/拒绝原因，拒绝必填）。

### 2.4 前端页面

路由 `/training/demand`（管理端侧栏「培训管理」分组下新增「培训需求」）：

- 查询区：关键字、状态下拉（待处理/已采纳/已拒绝）、部门下拉。
- 表格列：需求标题、培训主题、培训对象、申请部门、状态 tag、创建时间、操作。
- 操作：新增、编辑、采纳、拒绝、删除；采纳/拒绝弹窗填写意见。
- 状态 tag 配色：待处理 `warning`、已采纳 `success`、已拒绝 `danger`。

## 3. PDF 课件管理

### 3.1 业务规则

- **归属课程**：PDF 课件必须挂载到已存在的课程下（与课程资料一致，上传前校验课程存在性）。
- **安全校验**：上传前校验扩展名白名单（仅 `pdf`）+ Magic Bytes（文件头 `%PDF`）+ 大小上限（默认 50MB，可配置）。
- **存储**：文件实体存 MinIO（对象路径 `course-pdfs/年/月/...`），`tr_course_pdf` 仅存元数据。
- **启用/停用**：`status` 0-禁用 1-启用；学员端课程详情仅展示启用状态的课件。
- **删除**：逻辑删除，同时联动删除 MinIO 对象，避免孤儿文件。
- **预览**：通过 MinIO 预签名 URL（7 天有效期）在线预览，与课程资料一致。

### 3.2 表结构（现状）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint PK | 主键 |
| `course_id` | bigint | 所属课程 ID |
| `name` | varchar(200) | 课件名称（可自定义） |
| `file_name` | varchar(200) | 原始文件名 |
| `file_path` | varchar(500) | MinIO 对象路径 |
| `file_size` | bigint | 文件大小（字节） |
| `upload_user_id` | bigint | 上传人 ID |
| `upload_time` | datetime | 上传时间 |
| `status` | tinyint | 0-禁用 1-启用 |
| `deleted` | tinyint | 逻辑删除 |

> 表已存在，**无需执行 SQL**。

### 3.3 接口契约（`/training/course-pdfs`）

| # | 方法 | 路径 | 说明 | 权限 |
|---|------|------|------|------|
| 1 | GET | `/training/course-pdfs` | 分页查询（课程/课件名/状态过滤） | TRAINING |
| 2 | POST | `/training/course-pdfs/upload` | 上传 PDF 课件（multipart） | TRAINING |
| 3 | GET | `/training/course-pdfs/{id}/url` | 获取预览地址（预签名 URL） | TRAINING |
| 4 | PUT | `/training/course-pdfs/{id}/status` | 启用/停用 | TRAINING |
| 5 | DELETE | `/training/course-pdfs/{id}` | 删除（联动删 MinIO） | TRAINING |

**上传参数（POST /upload）**：`file*`（MultipartFile）、`courseId*`、`name`（可选，默认取文件名）。

### 3.4 前端页面

路由 `/training/pdf`（管理端侧栏「培训管理」分组下新增「PDF 课件」）：

- 查询区：课程下拉、课件名关键字、状态下拉。
- 表格列：课件名称、文件名、所属课程、大小、状态（开关式切换）、上传人、上传时间、操作。
- 操作：上传（弹窗选课程 + 选文件）、预览（新窗口打开预签名 URL）、停用/启用、删除。
- 上传成功/失败提示区分：Magic Bytes 校验失败给出明确提示「文件内容与声明格式不符」。

## 4. 培训计划审批闭环

### 4.1 现状分析（已核对代码）

`TrTrainingPlanServiceImpl` 现有能力与缺口：

| 环节 | 现状 | 问题 |
|------|------|------|
| 草稿 → 待审批（submit） | ✅ 已实现 | — |
| 待审批 → 已通过（approve） | ✅ 仅置状态 `2` | ❌ 不对学员端产生任何影响 |
| 待审批 → 已驳回（reject） | ✅ 已实现 | — |
| 状态 `4-已发布` | 仅被 `parseStatusList` 视为已通过参与过滤 | ❌ 无任何代码将计划置为 `4` |

`tr_training_plan` 表 `target_departments` 字段存「培训对象部门 ID 列表」（JSON 文本），`tr_plan_course` 存计划关联课程，`tr_training_task` 与 `sys_message` 分别承载任务与站内信。

### 4.2 设计方案

**审批通过（approve）改造**——一键下发：

1. 校验计划状态为待审批（现状保留）。
2. 校验计划必须已关联至少 1 门课程（否则提示「请先为计划绑定课程再提交审批」）。
3. 将状态置为 `4-已发布`（替代原 `2`），记录审批人、审批时间、审批意见。
4. **自动生成培训任务**：
   - 解析 `target_departments` 得到目标部门 ID 列表；若为空则跳过下发（仅发布）。
   - 查询这些部门下的全部在岗员工（`sys_user.department_id in (…)` 且 `status=1`）。
   - 按「计划 × 课程 × 员工」生成 `tr_training_task`，任务名取课程名，截止时间取计划 `end_date`。
   - **幂等**：同一员工同一课程若已存在未删除任务，跳过不重复生成。
5. **站内信通知**：为每个新生成任务的员工发送 `sys_message`（类型 1-任务通知，`related_id` = 任务 ID），内容带课程名与截止日期。
6. 事务内完成（任一环节失败整体回滚，不产生半成品数据）。

**驳回（reject）**：维持现状不变。

**前端（计划列表页）改造**：
- 通过后状态展示为「已发布」，tag 配色沿用已通过的 `success`。
- 计划详情/列表新增「目标部门」与「关联课程数」展示，便于审批人确认范围。
- 审批通过弹窗增加确认文案：将按目标部门员工自动下发培训任务并发送站内信。

### 4.3 影响面与约束

| 项 | 说明 |
|----|------|
| 学员端影响 | 审批通过 → 学员「我的任务」立即出现新任务 + 消息中心收到通知 |
| 管理端既有接口 | `/training/plans` 的 GET/POST/PUT/submit/reject 契约不变 |
| 幂等保护 | 按 `course_id + user_id` 查重，避免重复下发 |
| 事务 | approve 整体 `@Transactional`，回滚不产生脏数据 |

## 7. 测试要点

1. 培训需求：新增 → 编辑 → 采纳（带意见）/ 拒绝（必填原因）→ 已处理需求禁止删除。
2. PDF 课件：非 PDF 扩展名拒绝、伪造扩展名（改名为 .pdf 的 txt）Magic Bytes 拦截、上传成功 → 预览 → 停用 → 删除。
3. 审批闭环：无课程的计划提交审批 → 通过时提示；绑定课程 + 目标部门的计划通过 → 学员端出现任务并收到站内信；重复审批不重复下发任务。
4. 权限：TRAINING 角色可见新菜单；非管理员角色访问接口返回 403。
