## 一、课题背景与意义

《药品生产质量管理规范》（GMP）要求企业对人员进行培训并建立完整的培训记录与档案，培训记录是 GMP 检查中的重点查验内容。当前相当数量的中小型药品生产企业，其培训管理仍以纸质流程或分散的电子表格为主，存在台账分散、审批不规范、审计取证困难等问题；同时，药品生产一线员工工位分散、难以长时间离岗，集中授课与 PC 端系统难以覆盖其学习需求。

本课题拟设计并实现一套以 Spring Boot 为后端、以微信小程序为移动学习端的 GMP 培训管理系统，实现培训计划、任务、学习、考核、审核、证书的全流程闭环与可追溯，并通过多端协同满足管理员办公与员工移动学习的不同场景需求。

---

## 二、主要任务与内容

1. **需求分析**：调研药品生产企业培训管理业务流程与 GMP 相关要求，确定系统角色、功能边界与业务规则，编写需求文档。
2. **系统设计**：完成总体架构设计、数据库设计（含表结构与关联关系）、接口设计，输出设计文档。
3. **后端开发**：基于 Spring Boot + MyBatis-Plus + Sa-Token 实现认证与权限、系统管理、培训管理、考试管理、操作日志、统计报表等模块。
4. **Web 前端开发**：基于 Vue 3 + Element Plus 实现管理端与学员端。
5. **微信小程序开发**：实现学员移动学习端，覆盖课件学习、在线答题、证书查看、消息通知等，并支持学习进度上报与续传。
6. **测试与优化**：完成功能测试、权限与越权测试、弱网测试与缺陷修复。

## 三、设计要求（技术指标）

### 3.1 架构要求

1. 采用前后端分离架构，前端与后端通过 HTTP + JSON 交互；
2. **一套后端服务同时支撑三个客户端**（Web 管理端、Web 学员端、微信小程序）；Web 学员端与小程序端复用同一套学员接口，请求与响应结构保持一致。

### 3.2 后端技术要求

1. 技术栈：Spring Boot、MyBatis-Plus、Sa-Token、MySQL 8.0、Redis、MinIO、EasyExcel；
2. 业务写操作位于服务层，并以事务保证数据一致性；
3. 数据表采用逻辑删除，公共字段（创建人、创建时间等）自动填充；
4. 接口统一返回结构 `{code, message, data}`，业务异常与系统异常由全局异常处理器统一处理，内部错误细节仅记录日志、不返回前端。

### 3.3 权限与数据隔离要求

1. 采用 **RBAC** 模型，系统角色不少于 5 类（超级管理员、质量负责人、培训管理员、部门负责人、普通员工）；
2. 后端对接口做角色级校验；前端路由按角色过滤菜单；
3. **学员端数据隔离须在服务层依据登录态强制实现**，不得依赖前端传入的用户标识，以防止越权访问。

### 3.4 安全要求

1. 用户密码强度为 6–20 位且同时包含字母与数字，以 BCrypt 加密存储，不得明文存储；
2. 登录需通过图形验证码校验；连续登录失败达 5 次时锁定账号 10 分钟；
3. 登录失败提示统一为「用户名或密码错误」，避免账号枚举；
4. 操作日志仅记录写操作，且对密码、令牌等敏感字段脱敏；
5. 文件上传须校验文件类型（含文件头/Magic Bytes 校验）与文件大小，仅允许白名单类型；
6. 接口分页查询的单页最大条数限制为 100，防止恶意拉取。

### 3.5 考试与合规要求

1. 答题接口**不得向客户端返回题目正确答案**，仅成绩查询接口可返回答案解析；
2. 培训计划/任务审核需拦截「提交人审核自身提交内容」的情形。

### 3.6 前端与交互要求

1. 管理端与学员端均基于 Vue 3 + Element Plus；
2. 微信小程序采用原生框架（WXML / WXSS / JS），须兼容 iOS 与 Android；
3. 时间字段在前端统一格式化为 `yyyy-MM-dd HH:mm:ss`；
4. 小程序端学习进度须支持上报与续传。
