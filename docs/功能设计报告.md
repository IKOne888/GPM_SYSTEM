## 1 引言

### 1.1 编写目的

本文档用于完整描述「药品生产企业 GMP 内部培训系统」的功能设计成果，作为毕业设计的功能设计交付物与后续维护依据。文档覆盖需求范围、角色权限、功能模块划分、关键业务流程、数据模型、接口契约与权限安全设计，并与当前代码实现保持一致。

### 1.2 项目背景

《药品生产质量管理规范》（GMP）要求药品生产企业对全体从业人员开展持续的岗位培训与考核，并保留可追溯的培训记录。企业内部传统的线下签到、纸质试卷方式存在以下问题：

- 培训任务下发与到期提醒依赖人工，容易遗漏；
- 学习时长、考试成绩等过程数据无法量化留痕；
- 培训档案、证书有效期缺乏统一管理，复训提醒不及时；
- 审计追踪能力弱，不满足质量体系对数据可追溯的要求。

本系统面向企业内部网环境，建设一套覆盖「培训计划 → 任务下发 → 在线学习 → 在线考试 → 成绩与证书归档 → 审计留痕」全链路的培训管理平台。

### 1.3 适用范围与读者对象

适用于系统开发、测试、验收及运维人员，也可作为毕业设计答辩的功能说明材料。

### 1.4 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| GMP | Good Manufacturing Practice，药品生产质量管理规范 |
| SOP | Standard Operating Procedure，标准作业程序 |
| 课程 | 培训内容的最小业务单元，含视频课件、资料附件、关联题库与考核参数 |

| 复训周期 | 课程要求的复训间隔天数，用于计算证书有效期与报名截止时间 |

## 2 系统概述

### 2.1 建设目标

1. **培训过程线上化**：培训计划、任务下发、视频学习、在线考试全流程线上完成。
2. **学习行为可量化**：视频学习进度按秒级上报，学习时长、完成率可统计。
3. **考核结果可追溯**：每次考试的答卷、得分、逐题解析全部留痕，可生成培训档案与合格证书。
4. **权限边界清晰**：管理端与学员端功能分离，管理操作受角色约束，学员数据在服务层强制隔离。
5. **多端覆盖**：PC 管理端、PC 学员端、微信小程序三端复用同一套后端服务。

### 2.2 用户角色与职责

系统采用基于角色的访问控制（RBAC），共定义 5 个角色（数据来源：`sys_role` 表）。

| 角色编码 | 角色名称 | 职责说明 |
| --- | --- | --- |
| `SUPER_ADMIN` | 超级管理员 | 系统最高权限，维护用户、部门、岗位等基础档案，可访问全部模块 |
| `QA_MANAGER` | QA 负责人 | 审批培训计划、查看审计日志与统计报表 |
| `TRAINING_ADMIN` | 培训管理员 | 维护课程与题库、编制培训计划、下发培训任务、上传视频课件 |
| `DEPT_LEADER` | 部门负责人 | 上传本部门培训视频，查看本部门培训情况 |
| `EMPLOYEE` | 普通员工 | 学员端角色，执行在线学习、在线考试、查看成绩与档案 |

### 2.3 总体功能结构

系统由「一个后端服务 + 两个 PC 前端 + 一个小程序端」构成，功能划分为管理侧与学员侧两大板块。

## 3 角色与权限设计

### 3.1 权限矩阵

| 功能模块 | 超级管理员 | QA 负责人 | 培训管理员 | 部门负责人 | 普通员工 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 系统管理（用户/部门/岗位查询） | ✓ | ✓ | ✓ | ✓ | — |
| 部门 / 岗位 增删改 | ✓ | — | — | — | — |
| 课程 / 视频 / 资料 维护 | ✓ | ✓ | ✓ | — | — |
| 培训计划 编制与审批 | ✓ | ✓ | ✓ | — | — |
| 培训任务 分配与催办 | ✓ | ✓ | ✓ | — | — |
| 题库 / 试卷 维护 | ✓ | ✓ | ✓ | — | — |
| 审计日志 查看与导出 | ✓ | ✓ | — | — | — |
| 统计报表 | ✓ | ✓ | ✓ | ✓ | — |
| 学员端全部功能 | ✓ | ✓ | ✓ | ✓ | ✓ |

### 3.2 权限实现机制

权限在前后端各做一次校验，形成双层防护：

**前端（路由级）**：`frontend-pc/src/router/index.js` 定义角色分组常量 `ROLE_GROUPS`，路由 `meta.roles` 声明可访问角色；全局前置守卫读取 `localStorage.userInfo.roles` 判定，无权访问时提示并回退。

| 分组 | 允许角色 |
| --- | --- |
| `SYSTEM` | SUPER_ADMIN、QA_MANAGER、TRAINING_ADMIN、DEPT_LEADER |
| `SYSTEM_ADMIN` | SUPER_ADMIN |
| `TRAINING` | SUPER_ADMIN、QA_MANAGER、TRAINING_ADMIN |
| `EXAM` | SUPER_ADMIN、QA_MANAGER、TRAINING_ADMIN |
| `AUDIT` | SUPER_ADMIN、QA_MANAGER |

**后端（接口级）**：`backend/src/main/java/com/gmp/config/SaTokenConfig.java` 通过 `SaRouter.match(...).check(StpUtil.checkRoleOr(...))` 对接口做角色校验，规则要点：

| 路径 | 校验规则 |
| --- | --- |
| `/system/**` | 需 SUPER_ADMIN / QA_MANAGER / TRAINING_ADMIN / DEPT_LEADER 之一 |
| `/system/department(s)`、`/system/position(s)` 的 POST/PUT/DELETE | 仅 SUPER_ADMIN |
| `/training/plans`、`/training/tasks` | 需 SUPER_ADMIN / QA_MANAGER / TRAINING_ADMIN 之一 |
| `/training/courses`、`/training/courses/**` 写操作 | 需 SUPER_ADMIN / QA_MANAGER / TRAINING_ADMIN 之一 |
| `/training/video(s)` 写操作 | 需 SUPER_ADMIN / QA_MANAGER / TRAINING_ADMIN 之一 |
| `/exam/**` | 需 SUPER_ADMIN / QA_MANAGER / TRAINING_ADMIN 之一 |
| `/audit/**` | 需 SUPER_ADMIN / QA_MANAGER 之一 |
| `/study/**` | 仅要求登录；数据归属由 Service 层强制校验 |

**未登录放行白名单**：`/auth/login`、`/auth/captcha`、Knife4j 文档路径（`/doc.html`、`/swagger-resources/**`、`/v3/**`、`/webjars/**`），以及视频流与下载接口（`/training/videos/*/stream|download`、`/study/videos/*/stream`，因浏览器原生 `<video>` 标签无法携带请求头 Token）。

### 3.3 学员端数据隔离

学员端接口统一使用 `/study/**` 前缀，与管理员端接口共存于同一后端工程。接口不接收外部传入的用户 ID，服务层统一通过 `StpUtil.getLoginIdAsLong()` 取当前登录人，并在 SQL 条件中强制拼入 `user_id`，从架构上杜绝横向越权（学员 A 无法读取学员 B 的任务、成绩、错题与消息）。

## 4 功能模块详细设计

### 4.1 管理端功能

#### 4.1.1 认证与登录

| 项目 | 说明 |
| --- | --- |
| 验证码 | `GET /auth/captcha` 生成 4 位图形验证码（Hutool LineCaptcha），验证码明文以 `auth:captcha:{key}` 写入 Redis，有效期 5 分钟；接口需在登录前访问，已加入白名单 |
| 登录 | `POST /auth/login` 校验图形验证码与用户名密码，成功后返回 `{token, user}`，`user` 为脱敏信息（含角色编码列表） |
| 登出 | `POST /auth/logout` |
| 安全策略 | 登录失败统一提示「用户名或密码错误」防止账号枚举；连续 5 次失败锁定账号 10 分钟；密码长度 6-20 位且需包含字母与数字 |

#### 4.1.2 首页工作台

展示 4 个核心指标卡（培训课程数、参训人员数、待完成任务数、考试通过率）、培训完成率趋势图（柱线复合图）、部门培训覆盖率环形图、待办事项列表与最近培训活动时间轴。

#### 4.1.3 系统管理

| 子功能 | 主要操作 | 接口前缀 |
| --- | --- | --- |
| 用户管理 | 分页查询、新增、编辑、删除、批量删除、启用/停用、重置密码 | `/system/users` |
| 部门管理 | 列表、树形结构、分页、新增、编辑、删除 | `/system/department` |
| 岗位管理 | 列表、分页、新增、编辑、删除、岗位培训矩阵查询与保存 | `/system/position` |

#### 4.1.4 培训管理

**课程管理**（`/training/courses`）

- 课程属性：课程编码、课程名称、课程分类、所属部门、适用岗位、SOP 编号与版本、学时、及格分、复训周期（天）、培训目标、状态。
- 操作：分页查询、新增、编辑、逻辑删除；课程分类字典由 `/training/course-categories` 提供（所有登录用户可读，学员端课程中心亦复用该接口）。

**课程资料**（`/training/courses/{id}/files`）

- 附件上传需通过 Magic Bytes 白名单校验（PDF / Word / Excel）与大小限制校验，文件存储于 MinIO。
- 上传、列表、删除、获取预签名访问地址（`GET /training/courses/files/{fileId}/url`）。

**视频课件**（`/training/videos`）

- 支持大文件分片上传：`POST /upload/init` 初始化 → `POST /upload/chunk` 上传分片 → `POST /upload/complete` 合并落库。
- 上传需校验 Magic Bytes 与课程存在性。
- 播放与下载：`GET /{id}/stream`、`GET /{id}/download`、`GET /playUrl/{id}`；删除为逻辑删除。

**培训计划**（`/training/plans`）

- 状态流转：草稿 → 提交审批 → 审批通过 / 审批驳回。
- 操作：查询、新增（含计划课程明细）、编辑、`PUT /{id}/submit` 提交审批、`POST /{id}/approve` 通过、`POST /{id}/reject` 驳回。

**培训任务**（`/training/tasks`）

- 由培训计划分配生成，操作：查询、`POST /assign` 分配任务、`PUT /{id}/complete` 标记完成、`POST /{id}/notify` 催办通知。

#### 4.1.5 考试管理

| 子功能 | 主要操作 | 接口前缀 |
| --- | --- | --- |
| 题库管理 | 分页查询、新增、编辑、删除、Excel 批量导入（`POST /import`）、模板下载（`GET /template`）、导出（`GET /export`） | `/exam/questions` |
| 试卷管理 | 分页查询、新增组卷、编辑、删除 | `/exam/papers` |

题型编码：`1-单选`、`2-多选`、`3-判断`、`4-填空`、`5-简答`。

#### 4.1.6 审计追踪

`GET /audit/logs` 查询操作日志，`GET /audit/logs/export` 导出 Excel。审计记录遵循以下约束：

- 仅记录写操作（新增 / 修改 / 删除）；
- 敏感字段（密码、Token）脱敏后入库；
- 客户端 IP 取 `X-Forwarded-For`、`X-Real-IP`、`RemoteAddr` 中的第一个非空值；
- 日志数据不可篡改，仅超级管理员与 QA 负责人可查询。

#### 4.1.7 统计报表

`GET /report/summary` 返回培训统计汇总数据，`GET /report/export` 导出报表。

### 4.2 学员端功能

学员端所有页面登录后即可访问，不做角色分组限制，数据隔离由后端服务层保证。页面路由与功能如下：

## 5 关键业务流程设计

### 5.1 登录与鉴权流程

```
① 前端进入登录页 → 调用 GET /api/auth/captcha 获取图形验证码
② 后端生成 4 位验证码，明文写入 Redis（key=auth:captcha:{captchaKey}，TTL 5 分钟），返回 Base64 图片
③ 用户提交用户名、密码、captchaKey、captchaCode → POST /api/auth/login
④ 后端校验验证码（一次性，校验后失效）→ 校验账号状态与密码
⑤ 失败：累计失败次数，达 5 次锁定 10 分钟，统一返回「用户名或密码错误」
⑥ 成功：Sa-Token 签发 UUID Token 并返回 {token, user}（user 含 roles）
⑦ 前端持久化：管理端存 token/userInfo，学员端存 student_token/student_userInfo（两套键名隔离，避免同域覆盖）
⑧ 后续请求在请求头 Authorization 中携带 Token，Sa-Token 校验登录态与角色
```

### 5.2 培训任务全生命周期

```
培训计划编制 → 提交审批 → QA 审批通过 → 分配生成培训任务（或学员在课程中心自主报名生成）
        ↓
任务状态 0 待学习 → 学员进入在线学习，上报进度 → 状态 1 学习中
        ↓
全部视频课件进度达标（单节 ≥ 95%） → 状态 2 待考试
        ↓
参加在线考试：及格 → 状态 3 已完成（生成培训档案与证书，推送通知）
            不及格 → 保持待考试，按允许次数补考（推送补考提醒）
        ↓
超过任务截止时间未完成 → 动态判定为状态 4 已逾期
```

任务状态取值：`0-待学习`、`1-学习中`、`2-待考试`、`3-已完成`、`4-已逾期`（4 为查询时按截止时间动态计算，不落库）。

### 5.3 视频学习进度上报与达标判定

- **上报时机**：播放中每 15 秒、暂停时、离开页面时（含 `beforeunload` 同步兜底）、播放结束时。
- **上报接口**：`POST /study/videos/progress`，进度值在服务层钳制到 0~100。
- **达标判定**：单节视频进度 ≥ **95%** 即视为该节完成；任务整体进度按各视频时长加权计算。
- **续播**：进入播放页时先查询 `GET /study/videos/{videoId}/record` 读取上次进度，从断点继续播放。

### 5.4 在线考试与错题闭环

```
点击「在线考试」→ 校验：全部视频已完成 且 存在已发布试卷
        ↓ 通过
POST /study/exams/{taskId}/start 创建考试记录（服务端记录开始时间）
        ↓
答题页全屏作答，倒计时以服务端时间为准，超时自动交卷
        ↓
POST /study/exams/records/{recordId}/submit 交卷
        ├─ 逐题判分（多选按字母升序比对、判断按「正确/错误」比对）
        ├─ 得分 ≥ 试卷及格分 → examPass=1，任务置为已完成，推送通过通知
        ├─ 得分 <  及格分 → 任务回到待考试，按剩余次数允许补考，推送补考提醒
        └─ 答错题目写入 tr_wrong_question（按 用户+题目 唯一，重复答错累加 wrong_count）
        ↓
GET /study/exams/records/{recordId}/result 查看成绩单与逐题解析
        ↓
错题本：GET /study/wrong-questions（mastered 筛选）+ GET /study/wrong-questions/stats
        ↓
错题练习：POST /study/wrong-questions/practice 即时判分，答对即置 mastered=1 自动移出未掌握列表
        ↓
手动移除：DELETE /study/wrong-questions/{id}
```

### 5.5 证书有效期与复训提醒

- 课程表 `tr_course.retrain_period` 记录复训周期天数（未配置或 ≤ 0 时默认按 365 天计算）。
- 考试通过后按「通过时间 + 复训周期」推算证书有效期；距到期 ≤ 30 天（`CERT_EXPIRING_DAYS = 30`）标记为「临期」，已过期标记为「已过期」，仅作档案状态展示（当前版本不写入站内信）。
- 学员端在「个人中心 → 培训档案」中查看证书列表与有效期。

### 5.6 消息通知

消息类型编码：`1-任务通知`、`2-到期提醒`、`3-补考提醒`、`4-系统通知`。

已实现的消息产生场景：

- **类型 1（任务通知）**：管理员分配培训任务、试卷发布（向该课程下已有学员推送「新考试发布通知」，或为适用岗位员工自动生成任务后推送「新培训任务通知」）、学员考试通过（「培训考试通过通知」）；
- **类型 2（到期提醒）**：管理员对未完成任务执行「催办」时下发「培训任务催办提醒」；
- **类型 3（补考提醒）**、**类型 4（系统通知）**：类型编码已预留，当前版本暂未产生该类消息。

学员通过顶部消息铃铛查看未读数，或在消息中心页面按状态与类型筛选、标记已读并跳转关联任务（类型 1/2/3 且 `relatedId` 非空时跳转 `/task/{relatedId}`）。

### 5.7 课程自主报名

学员在课程中心点击「立即报名」，系统创建培训任务并将报名截止时间设为「当前时间 + 课程复训周期」（课程未配置复训周期时不设置截止时间）。

## 7 接口设计

### 7.1 接口规范

| 项目 | 规范 |
| --- | --- |
| 统一前缀 | `/api`（由 `server.servlet.context-path` 配置） |
| 认证方式 | 请求头 `Authorization` 携带 Sa-Token；学员端 Token 不带 `Bearer ` 前缀 |
| 请求格式 | `application/json`（文件上传为 `multipart/form-data`） |
| 响应格式 | 统一返回 `Result<T>`：`{ code, msg, data }` |
| 业务异常 | 抛出 `BusinessException(ErrorCode.XXX, "中文提示")`，由全局异常处理器转换为 `Result` |
| 分页约定 | 请求参数 `page` / `size`，响应 `{ records, total, size, current }`，`size` 上限 100 |
| 重要约定 | 全局异常处理器返回 **HTTP 200 + 业务 code**，前端需依据 `code` 判定成功与否，不能仅凭 HTTP 状态码 |

**全局异常处理覆盖场景**（共 16 类）：业务异常、未登录、无接口权限、无角色权限、请求体参数校验失败、表单参数绑定失败、参数约束违反、缺少必填请求参数、请求参数类型不匹配、请求体 JSON 解析失败、唯一键冲突、数据完整性违反、上传文件大小超限、请求方法不支持、未匹配到处理器、系统未知异常。系统异常仅记录服务端日志，不向前端返回内部细节。

**接口规模**：共 103 个 REST 接口，其中管理端与通用接口 69 个，学员端 `/study/**` 接口 34 个。

## 8 非功能设计

### 8.1 安全性

| 措施 | 说明 |
| --- | --- |
| 认证与授权 | Sa-Token 会话认证 + 接口级角色校验，Token 存 Redis 支持主动失效 |
| 越权防护 | 学员端不接收 userId 参数，服务层强制以登录人身份查询，杜绝水平越权 |
| 密码安全 | 密码加密存储，长度 6-20 位且必须含字母与数字；重置密码接口仅管理员可用 |
| 暴力破解防护 | 图形验证码一次性校验 + 连续 5 次失败锁定账号 10 分钟 + 登录错误信息不区分账号 |
| 文件上传安全 | 视频与资料上传均做 Magic Bytes 校验（白名单格式）与大小限制，并校验关联课程是否存在 |
| 数据可追溯 | 写操作全量记录审计日志，敏感字段脱敏；业务数据采用逻辑删除，不物理清除 |
| 传输与跨域 | CORS 采用白名单来源配置（开发环境显式登记各前端端口），生产环境通过环境变量注入，禁止通配 |
| 配置安全 | 数据库密码、Redis 密码、MinIO 密钥等敏感配置一律通过环境变量注入，不硬编码 |
| 生产环境加固 | 生产环境关闭 SQL 日志输出与 Knife4j 接口文档 |

### 8.2 性能与容量

- 分页查询统一限制单页最大 100 条，防止大结果集拖垮服务。
- 视频采用 MinIO 对象存储，支持流式播放与分片上传，避免大文件经应用服务内存中转。
- HikariCP 连接池：最小空闲 5、最大 20、连接超时 30s、空闲超时 10min、最大生命周期 30min。
- 单文件与单请求大小上限 500 MB，可通过环境变量调整。
- 前端图表按需引入 ECharts 组件并监听容器尺寸变化，避免首帧尺寸异常导致的重绘问题。

### 8.3 可用性与容错

- 视频学习进度在播放中定时上报，并在暂停、离开页面、播放结束时补报，`beforeunload` 阶段使用同步请求兜底，降低进度丢失概率。
- 考试倒计时以服务端时间为准，中途退出后重新进入仍按剩余时间继续。
- 全局异常处理器对 16 类异常给出明确中文提示，避免前端出现无反馈的白屏或静默失败。
- 外部依赖（Redis、MinIO、MySQL）不可用时，登录与文件功能会明确失败并给出提示，便于定位。

### 8.4 兼容性

- 后端运行于 JDK 21，选用 Lombok 1.18.46 解决 Spring Boot 2.7 默认 Lombok 与高版本 JDK 的兼容问题。
- 前端开发服务器端口分别为 3000（管理端）与 3002（学员端），均已登记到后端 CORS 白名单。
- 学员端与管理端使用独立的本地存储键名（`student_token` / `student_userInfo` 与 `token` / `userInfo`），支持同域部署而不互相覆盖。
- 小程序端复用学员端接口，无需后端改造。

### 8.5 可维护性

- 后端严格分层：Controller（参数校验与转发）→ Service（业务逻辑与事务）→ Mapper（数据访问），服务层写方法统一加 `@Transactional(rollbackFor = Exception.class)`。
- DTO / VO 按业务模块分包（`exam`、`plan`、`study`、`task`、`video`），与接口一一对应。
- 前端按 `api`（接口封装）/ `views`（页面）/ `store`（状态）/ `utils`（工具）职责分层，菜单与路由由路由表统一驱动。

### 10.2 环境依赖说明

- 后端启动依赖 Redis、MySQL 与 MinIO 三个外部服务，任一未就绪会导致登录（Redis）或文件上传（MinIO）功能失败。
- 开发环境使用 `application-dev.yml`，生产环境通过 `SPRING_PROFILES_ACTIVE=prod` 切换，并以环境变量注入数据库、Redis 与 MinIO 凭据。
