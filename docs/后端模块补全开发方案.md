# GMP 内部培训系统 —— 后端模块补全开发方案

> 编写日期：2026-10-11
> 关联问题：前端点击侧边栏菜单时提示「请求资源不存在」（HTTP 404）

---

## 一、问题背景与根因

### 1.1 现象

登录后点击侧边栏任意功能菜单（视频课件、培训计划、培训任务、题库管理、试卷管理、操作日志等），
页面加载时发起的数据请求返回 404，前端统一提示：**「请求资源不存在」**。

### 1.2 根因

前端页面（`frontend-pc/src/views/**`）已经按既定接口契约完成开发，但后端对应的 Controller 尚未实现，
请求落到 Spring MVC 找不到处理器，被 `GlobalExceptionHandler` 兜底为 404。

当前后端**已有**的控制器：

| 控制器 | 路径 | 状态 |
| --- | --- | --- |
| AuthController | `/auth/**` | ✅ |
| SysUserController | `/system/users` | ✅ |
| SysDepartmentController | `/system/departments` | ✅ |
| SysPositionController | `/system/positions` | ✅ |
| TrCourseCategoryController | `/training/course-categories` | ✅ |
| TrCourseController | `/training/courses` | ✅ |
| CourseFileController | `/training/courses/{id}/files` | ✅ |
| VideoUploadController | `/training/video`（单数） | ⚠️ 路径与前端不一致 |
| ReportController | `/report/**` | ✅ |

当前后端**缺失**的控制器（导致菜单 404 的元凶）：

- `/exam/questions`（题库）、`/exam/papers`（试卷）
- `/training/plans`（培训计划，含审批流转）
- `/training/tasks`（培训任务）
- `/audit/logs`（审计日志查询）
- `/system/users/list`（用户下拉，培训任务页依赖）

---

## 二、目标

1. 补齐上述缺失模块的后端接口，使所有菜单可正常打开、增删改查可用；
2. 严格对齐**前端既有接口契约**（路径、请求方式、字段名），不做前端大改；
3. 延续企业级规范：统一 `Result` 返回、`BusinessException` + `ErrorCode` 错误处理、
   `@Valid` 参数校验、Service 层 `@Transactional`、Sa-Token 角色鉴权、详细中文注释。

## 四、详细设计

### 4.0 通用约定

- 返回：统一 `Result<T>`；分页返回 `Page<VO>`（`records` + `total`）。
- 校验：Controller 用 `@Valid` + JSR-303 注解；`@Validated` 打开方法级校验。
- 异常：业务异常一律 `throw new BusinessException(ErrorCode.XXX, "中文提示")`。
- 事务：Service 写方法加 `@Transactional(rollbackFor = Exception.class)`。
- 逻辑删除：实体用 `@TableLogic` 字段 `deleted`，MyBatis-Plus 自动过滤。
- 审计：`AuditLogAspect` 已对 `com.gmp.controller..*` 的写方法自动落库，新控制器无需手动记录。

### 4.1 考试管理 - 题库 `/exam/questions`

**实体 `TrQuestion`（表 `tr_question`）**：id、courseId、questionType(tinyint 1/2/3)、content、
options(text/JSON)、answer、analysis、score、difficulty(tinyint 1/2/3)、status、审计字段、deleted。

**字段映射（前端字符串 ↔ 数据库 tinyint）**：

| 前端 | 数据库 |
| --- | --- |
| type: single/multiple/judge | questionType: 1/2/3 |
| difficulty: easy/medium/hard | difficulty: 1/2/3 |

> 前端题型含 `fill`（填空）、`short_answer`（简答），数据库仅设计单选/多选/判断三档；
> **方案**：扩展 `questionType` 取值 4-填空、5-简答（不破坏现有数据），映射层兼容。

**VO `QuestionVO`**：含 `type`、`difficulty` 字符串（由枚举映射回填）+ 解析后的 `options` 数组。

**接口**：
- `GET /exam/questions` → 分页（keyword 模糊 content、type/difficulty/category 过滤）。
- `POST/PUT/DELETE /exam/questions[/{id}]`。
- `POST /exam/questions/import` → EasyExcel 解析 `file`，逐行校验并入库，返回成功/失败条数。
- `GET /exam/questions/template` → 生成并下载导入模板 xlsx。
- `GET /exam/questions/export` → 导出当前题库 xlsx。

### 4.2 考试管理 - 试卷 `/exam/papers`

**实体 `TrExamPaper`（表 `tr_exam_paper`）**：id、name、courseId、totalScore、passScore、
examDuration、maxRetry、questionCount、status、审计字段、deleted。
（表存在，缺 `code`、`compositionType`、`rules` 字段）

> **方案**：为对齐前端字段 `code`、`compositionType`、`status(draft/published/archived)`，
> 需**扩展 `tr_exam_paper` 表**：新增 `code varchar(64)`（唯一）、`composition_type varchar(20)`、
> `rules text`（JSON 存储组卷规则）；`status` 由 tinyint 改为语义映射（0-草稿 1-已发布 2-已归档）。
> 同步修改两份 SQL 脚本（`gmp_training_system_schema.sql`、`gmp_training_system.sql`）。

**关联表 `tr_paper_question`**：paper_id、question_id、sort、score（已存在）。

**接口**：
- `GET /exam/papers` 分页（name 模糊、status 过滤）。
- `POST/PUT/DELETE /exam/papers[/{id}]`：保存试卷 + 组卷规则；`questionCount` 由规则/关联计算。

### 4.3 培训计划 `/training/plans`

**实体 `TrTrainingPlan`（表 `tr_training_plan`，已存在）**：
id、name、planType、description、startDate、endDate、status(tinyint 0-草稿 1-待审批 2-已通过 3-已驳回 4-已发布)、
submitTime、approveTime、approveUserId、approveRemark、审计字段、deleted。

> **差异**：前端用 `code`（计划编号）、`year`（年度）、`approvalStatus`（draft/pending/approved/rejected）、
> `departmentName/creatorName`、`targetDepartments[]`、`courses[{courseId,trainer,plannedDate}]`。
> **方案**：扩展 `tr_training_plan` 新增 `code`、`year`、`target_departments`(JSON) 字段；
> `approvalStatus` 由 `status` 映射；`courses` 通过 `tr_plan_course` 关联（需扩展 `trainer`、`planned_date` 字段）。
> 同步两份 SQL 脚本。

**状态流转**：
```
draft/rejected --submit--> pending --approve--> approved
                                   --reject--> rejected
```

**接口**：
- `GET /training/plans` 分页；`GET /training/plans/list` 全量。
- `POST /training/plans`、`PUT /training/plans/{id}`：保存计划主表 + 计划课程子表（先删后插）。
- `PUT /training/plans/{id}/submit`：仅 draft/rejected 可提交 → pending，写 submitTime。
- `POST /training/plans/{id}/approve` / `/reject`：仅 pending 可审批 → approved/rejected，写 approveTime/approveUserId/approveRemark。

### 4.4 培训任务 `/training/tasks`

**实体 `TrTrainingTask`（表 `tr_training_task`，已存在）**：
id、planId、courseId、userId、taskType、status(tinyint 0-待学习 1-学习中 2-待考试 3-已完成 4-已逾期)、
deadline、startTime、completeTime、studyDuration、videoProgress、examScore、examPass、retryCount、maxRetry、审计字段。

> **差异**：前端展示 `name`（任务名）、`assigneeName`（执行人）、`planName`、`courseName`、
> `departmentName`、`progress`、`status(not_started/in_progress/completed/overdue)`。
> 表缺 `name`、`description` 字段 → **扩展新增 `name`、`description`**；其余通过关联查询回填；
> `progress` 用 `videoProgress` 映射；`status` 做 tinyint↔字符串映射。同步两份 SQL 脚本。

**接口**：
- `GET /training/tasks` 分页（name 模糊、status、assigneeName 关联 sys_user.real_name 过滤）。
- `POST /training/tasks/assign`：按 `assigneeIds[]` 拆分为多条任务记录（一人一条），写 planId/courseId/deadline。
- `PUT /training/tasks/{id}/complete`：status=已完成，写 completeTime。
- `POST /training/tasks/{id}/notify`：发送催办（本轮先记录/返回成功，后续可接入消息表 `sys_message`）。

### 4.5 视频课件 `/training/videos`（路径对齐 + 分片上传）

**现状**：`VideoUploadController` 映射为 `/training/video`（单数），前端用 `/training/videos`（复数）。

**方案**：
1. 将 `VideoUploadController` 的 `@RequestMapping` 改为 `/training/videos`；
2. 新增分页 `GET /training/videos`（name、courseId 过滤，回填 `courseName`、`format`、`status`）；
3. 保留 `POST /upload`、`DELETE /{id}`；
4. 新增分片上传三接口：
   - `POST /upload/init`：入参 fileName/fileSize/totalChunks/courseId/name/description，返回 `uploadId` 与已上传分片 `uploadedChunks`；
   - `POST /upload/chunk`：入参 `file`、`uploadId`、`chunkIndex`、`totalChunks`，分片存入本地临时目录/MinIO；
   - `POST /upload/complete`：合并分片为完整对象写入 MinIO，落库视频记录；
5. 新增 `GET /{id}/stream`（MinIO 预签名或流式响应，供 `<video>` 播放）、`GET /{id}/download`。

> 分片临时目录：`${java.io.tmpdir}/gmp-video-chunks/{uploadId}/`；`uploadId` 与元信息暂存 Redis（键 `video:chunk:{uploadId}`，含已上传分片列表，用于断点续传）。

### 4.6 审计日志 `/audit/logs`

**实体 `SysAuditLog`（表 `sys_audit_log`，已存在，由 `AuditLogAspect` 写入）**。
前端字段与实体字段不一致，需 VO 映射：

| 前端字段 | 实体字段 | 说明 |
| --- | --- | --- |
| action | operationType | INSERT/UPDATE/DELETE → create/update/delete 映射 |
| operator | username / realName | 优先 realName |
| operatorIp | ip | 直接映射 |
| duration | executeTime | 直接映射 |
| operateTime | operationTime | 直接映射 |
| responseResult | 无 | 返回 null（预留） |

**接口**：
- `GET /audit/logs`：分页 + `module/action/operator/startDate~endDate` 过滤。
- `GET /audit/logs/export`：导出 xlsx。

### 4.7 辅助接口 `/system/users/list`

培训任务页下拉需要用户列表。在 `SysUserController` 新增 `GET /system/users/list`
（返回 `id`、`realName`、`username`），Service 补充 `listUsers()`。

## 六、权限规则补充（`SaTokenConfig`）

// 考试管理：题库/试卷，仅管理员角色
SaRouter.match("/exam/**", r -> StpUtil.checkRoleOr("SUPER_ADMIN", "QA_MANAGER", "TRAINING_ADMIN"));
// 审计日志查询：系统管理员 / QA负责人（只读）

## 八、实施步骤与验证

按模块顺序实施，每完成一个模块执行：**Maven 编译 → 启动临时实例（8081）实测 → 前端联调**。

1. **考试管理**：`TrQuestion/TrExamPaper`(+关联) 实体/Mapper/Service/DTO/VO/Controller；SQL 变更；`SaTokenConfig` 补 `/exam/**`。
2. **培训计划**：`TrTrainingPlan` 实体/Mapper/Service/Controller + 审批流转；SQL 变更。
3. **培训任务**：`TrTrainingTask` 扩展 + Service/Controller；补 `/system/users/list`。
4. **视频课件**：路径对齐 + 分页 + 分片上传三接口 + stream/download；前端 video 页去掉 Bearer 硬编码。
5. **审计日志**：`AuditLogController(/audit/logs)` + 导出 + VO 映射；`SaTokenConfig` 补 `/audit/**`。
6. **联调收尾**：前端各页实测、`npm run build` 通过、提示用户重启 8080 后端。

**验收标准**：侧边栏所有菜单均可正常加载，无「请求资源不存在」；各模块增删改查、审批、上传功能可用。

## 九、风险与注意事项

1. **路径单复数**：后端既有 `/training/video`、`/training/plan/**` 等单数规则，需与前端复数路径对齐，避免 404/403。
2. **token 前缀**：Sa-Token `token-name=Authorization` 且无 `token-prefix`，前端严禁加 `"Bearer "`。
3. **表结构扩展需同步执行 SQL**：用户库 `gmp_training_system` 需执行变更语句后再重启后端。
4. **EasyExcel 依赖**：导入导出依赖 EasyExcel，确认 `pom.xml` 已引入（报告模块已用过）。
5. **MinIO 依赖**：视频上传/预览依赖 MinIO（9000/9001）与 `gmp-training` bucket 正常运行。
