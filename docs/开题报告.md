## 一、课题背景与意义

### 1.1 GMP 对人员培训的强制性要求

《药品生产质量管理规范》（GMP，2010 年修订）是我国药品生产企业强制执行的法定规范。《药品 GMP 指南（第 2 版）·质量管理体系》在第 3.2.4 节「人员培训」中引述 GMP 的要求：**「所有人员应明确并理解自己的职责，熟悉与其职责相关的要求，并接受必要的培训，包括上岗前培训和继续培训。」**

该指南进一步指出：上岗前培训意味着员工**必须通过培训才能获得上岗或独立操作的资格**；继续培训则意味着企业对员工的培训**应当是长期的、有计划的工作，而不是一次性或临时性的工作**。欧盟 GMP 同样将培训划分为上岗前培训与继续培训两类。

在培训组织与记录方面，指南引述 GMP 要求：**「企业应当指定部门或专人负责培训管理的工作，应当有经生产管理负责人或质量管理负责人审核或批准的培训方案或计划，培训记录应当予以保存。」**同时要求**「定期评估培训的实际效果」**。这表明培训是一项必须有责任主体、有审批、有记录、有评估、可追溯的合规活动，培训记录是 GMP 检查中的重点查验对象之一。

### 1.2 指南规定的培训管理要素与基本流程

为使本系统的设计「有标准可依」，现将指南第 3.2.4 节的核心要求归纳如下。

**（1）实施培训需关注的六项要素**

| 要素 | 指南要求（据 3.2.4 节归纳） |
| --- | --- |
| 培训管理 | 培训要有具体的管理程序，并有明确的人员或部门进行管理 |
| 培训范围 | 培训要涵盖所有与产品生产和质量相关的人员 |
| 培训内容 | 应针对不同组织或岗位实施针对性培训，内容与岗位职责和操作相适应 |
| 培训计划 | 培训要有经过批准的计划或方案 |
| 培训结果 | 培训的效果要定期评估 |
| 培训文件 | 培训要有相关的文件和记录 |

**（2）培训管理的七步闭环流程（据指南图 3-2、表 3-6）**

```
培训范围 → 识别培训需求 → 筛选培训内容 → 制定培训计划 → 实施培训 → 评估培训结果 → 培训总结
   ↑                                                                              │
   └──────────────────────────── 闭 环 改 进 ────────────────────────────────────┘
                  全过程由「培训文件」（记录与档案）支撑，保证可追溯
```

指南还要求：在职责上，应**指定部门或专人负责培训管理**，由**生产管理负责人或质量管理负责人审核或批准培训计划**，**部门负责人有责任确认本部门员工的培训需求并保证其参与相应培训**；在内容上，可划分为面向全员的**基础培训内容**与面向特定岗位的**针对性培训内容**，并可按培训需求相近程度划分「**培训目标组**」；在计划上，培训计划应包含**培训对象（目标组）、培训课程（内容）、培训周期**三要素，并可分为周期培训计划、年度培训计划与年度个人培训计划；在评估上，可采用提问、测验或全员性 GMP 考试，判定员工是否达到培训效果、是否需要再次培训，并应每年对培训完成情况与结果进行总结。

### 1.3 中小型药企培训管理的现实不足

对照上述标准要求，相当数量的中小型药品生产企业仍以纸质流程或分散电子表格开展培训管理，主要问题包括：

1. **培训流程不成闭环**：培训需求、计划、实施、评估、总结分散在不同部门与表单中，难以形成指南所要求的闭环管理；
2. **审批责任难落实**：培训计划缺乏经生产/质量负责人审核批准的线上链路，审批过程不可追溯；
3. **记录取证困难**：培训记录、考核结果、培训档案分散保存，面对 GMP 检查时难以及时提供完整证据链；
4. **针对性与周期性不足**：培训内容与岗位的对应关系、继续培训的周期安排缺乏系统支撑；
5. **一线学习场景受限**：生产一线员工工位分散、难以长时间离岗，集中授课与 PC 端系统难以覆盖其碎片化学习需求。

### 1.4 微信小程序作为移动学习载体的适用性

微信小程序具有**免安装、即用即走、跨平台**的技术特征，一套代码可同时运行于 iOS 与 Android；其具备网络请求、文件上传下载、视频播放、本地缓存等能力，可支撑在线学习类应用。指南在「培训执行和保证」中列举了**自学、通过视频教材或 GMP 培训软件学习**等培训方式，小程序正适合承载此类**随时随地的自主学习**，且无需上架应用商店、无需分发安装包，便于在企业内部推广。

### 1.5 研究意义

**理论意义**：研究如何以信息系统**落实 GMP 培训管理的标准要素与闭环流程**，并探索「一套后端服务同时支撑 Web 管理端、Web 学员端与微信小程序」的多端协同架构，以及移动端学习进度的记录、上报与续传机制。

**实践意义**：为中小型药品生产企业提供一套低成本、可落地、**功能与 GMP 指南要求相对应**的培训管理信息化方案，覆盖培训需求、计划审批、任务实施、在线学习、考核评估、档案记录的全流程，以微信小程序降低一线员工使用门槛，并通过操作留痕提升培训记录的可追溯性。系统基于开源技术栈构建，无软件授权费用，具备推广可行性。

## 二、国内外研究现状

### 2.1 药企培训管理信息化现状

**国外**：SAP、Veeva Vault、MasterControl 等 GxP 合规管理产品包含培训管理（Training Management）模块，支持培训矩阵（Training Matrix）、电子签名与审计追踪，并可满足 FDA 21 CFR Part 11 对电子记录与电子签名的要求；其功能完备但采购与实施成本较高，中小企业难以承担。

**国内**：近年出现若干面向制药企业的培训管理软件与 SaaS 平台，功能多集中在培训登记、在线考试与证书发放。对照 GMP 指南要求，其在**培训需求闭环、培训计划的分级审批、培训内容与岗位（培训目标组）的对应、移动化自主学习、培训记录可追溯**等方面仍有提升空间。

### 2.2 移动学习与微信小程序的应用现状

移动学习（Mobile Learning）指学习者借助移动终端在任意时间、地点进行学习。国外以 Moodle、Canvas 等平台的移动端为代表；国内以各类在线学习平台与即时通讯平台的移动端为主。微信小程序自 2017 年发布以来，已在企业内部管理、在线教育、政务服务等领域广泛应用，相较原生 App 在**开发成本、分发成本与跨平台一致性**上具有明显优势。

### 2.3 现有工作的不足

1. **与 GMP 标准要素缺乏显式对应**：通用培训系统较少按「培训范围—需求—内容—计划—实施—评估—总结」的标准闭环组织功能，标准符合性不直观；
2. **多端重复建设**：管理端与学习端常各自独立开发，缺乏统一后端与接口契约；
3. **移动学习支持薄弱**：面向生产一线员工的移动学习端较少，学习进度难以连续记录与续传；
4. **合规相关设计不足**：在考试防作弊、操作留痕、上传文件校验、培训记录可追溯等关键点上缺乏系统性设计。

## 三、研究目标与研究内容

### 3.1 研究目标

设计并实现一套以 Spring Boot 为后端、以微信小程序为移动学习端的药品生产企业 GMP 培训管理系统，使其功能与《药品 GMP 指南（第 2 版）·质量管理体系》第 3.2.4 节的培训管理要素与闭环流程**相对应**，具体目标为：

1. 支撑培训「**需求 → 计划 → 任务 → 学习 → 考核 → 评估 → 档案**」的线上闭环；
2. 实现一套后端支撑三端（Web 管理端、Web 学员端、微信小程序）的统一架构；
3. 实现基于 Sa-Token 的 RBAC 权限体系与服务层数据隔离；
4. 实现微信小程序端的课件学习、在线答题、证书查看与消息通知，支持学习进度记录与续传；
5. 通过操作日志与培训档案保证培训记录可追溯；
6. 形成完整的设计文档、接口文档与可运行成果。

### 3.2 研究内容

| 序号 | 研究内容 | 主要内容 |
| --- | --- | --- |
| 1 | 培训闭环业务建模 | 需求、计划、任务、学习、考核、审核、档案的状态定义与流转 |
| 2 | 培训需求管理 | 员工/部门在线申报培训需求，责任人采纳或拒绝并反馈 |
| 3 | 培训计划与审批 | 培训计划编制，以及与「经负责人审核批准」相对应的线上审核流程 |
| 4 | 培训内容管理 | 课程与课件（视频/PDF）管理，内容与部门、岗位对应 |
| 5 | 培训实施与督促 | 按范围分配培训任务、下发通知、到期提醒与催办 |
| 6 | 在线学习与进度续传 | 小程序在线学习、进度周期上报与续传、学习记录留痕 |
| 7 | 考核与效果评估 | 题库/试卷/在线考试、成绩与补考，作为培训结果评估依据 |
| 8 | 培训档案与可追溯 | 学习记录、证书、操作日志（审计追踪） |
| 9 | 权限与数据隔离 | RBAC 角色—菜单授权，服务层按登录态强制隔离学员数据 |
| 10 | 工程与安全规范 | 验证码、登录锁定、统一异常、上传文件校验、敏感字段脱敏 |

### 3.3 系统功能与 GMP 指南要求的符合性对照

下表将本系统拟实现的功能与指南第 3.2.4 节要求逐项对应，作为系统设计的标准依据：

| 指南要求（3.2.4 节） | 系统对应功能 / 设计 |
| --- | --- |
| 指定部门或专人负责培训管理（培训管理要素） | RBAC 设置培训管理员等角色，配套系统管理模块 |
| 培训范围涵盖所有与生产、质量相关的人员 | 支持按全员 / 部门 / 岗位确定被培训人并分配任务 |
| 识别培训需求；部门负责人确认本部门需求 | 培训需求申报模块：在线申报、采纳/拒绝与结果反馈 |
| 内容与岗位职责相适应；划分「培训目标组」 | 以**部门—岗位结构**落地培训目标组，课程按部门/岗位定向 |
| 基础培训内容 + 针对性培训内容；培训教材 | 课程库与课件（视频/PDF）分类管理，文件存于对象存储 |
| 培训计划经生产/质量负责人审核或批准 | 培训计划模块 + 线上审核（结合企业实际设计为部门初审、质量复核两级） |
| 实施培训、组织督促员工参与 | 培训任务分配、站内信通知、到期提醒与催办 |
| 自学、视频教材/培训软件等培训方式 | 微信小程序在线自学、视频课件播放与进度记录 |
| 定期评估培训效果；测验/考试；判定是否再培训 | 题库、试卷、在线考试、成绩判定与补考 |
| 继续培训的周期性 | 培训任务到期提醒、补考提醒，支撑周期性继续培训 |
| 每年对培训完成情况与结果总结 | 统计报表、培训完成率与通过率分析 |
| 培训文件与记录应保存、可追溯 | 学习记录、培训证书、操作日志（审计追踪）留存 |

> 边界说明：本系统主要支撑**线上可完成的培训方式**（自学、视频/文档学习、在线考试）与培训管理流程；指南中「岗位实际操作学习」「外部专业机构专项培训及其资质证书」等线下环节，系统仅做计划与结果登记，不替代线下实操与外部取证。

## 四、技术路线与实施方案

### 4.1 总体架构

系统采用前后端分离架构，一套 Spring Boot 后端同时支撑三个客户端；Web 学员端与微信小程序复用同一套学员接口，仅展示层不同。

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│   管理端 PC   │   │   学员端 PC   │   │   微信小程序  │
│ Vue3+Element │   │ Vue3+Element │   │  原生 WXML    │
│  （培训管理） │   │  （在线学习） │   │ （移动学习端）│
└───────┬──────┘   └───────┬──────┘   └───────┬──────┘
        └──────────────────┼──────────────────┘
                           │  HTTP / JSON
                    ┌──────▼──────┐
                    │ Spring Boot │ 鉴权(Sa-Token)·统一异常·操作日志
                    │   后端服务   │ 业务复用·学员数据隔离
                    └──┬───┬───┬──┘
          ┌────────────┘   │   └────────────┐
     ┌────▼────┐     ┌─────▼─────┐    ┌─────▼─────┐
     │  MySQL  │     │   Redis   │    │   MinIO   │
     │ 业务数据 │     │ 会话/验证码│    │ 课件对象存储│
     └─────────┘     └───────────┘    └───────────┘
```

### 4.2 技术选型

| 层次 | 技术 | 选型说明 |
| --- | --- | --- |
| 后端框架 | Spring Boot 2.7 | 生态成熟，企业主流 |
| 持久层 | MyBatis-Plus | 简化 CRUD，支持逻辑删除与字段自动填充 |
| 认证授权 | Sa-Token + Redis | 角色/权限声明式校验，会话集中存储 |
| 数据库 | MySQL 8.0 | 关系模型契合业务，支持事务 |
| 缓存 | Redis | 会话、验证码、登录失败计数 |
| 对象存储 | MinIO | 私有部署、S3 兼容，承载视频/PDF 课件 |
| Web 前端 | Vue 3 + Element Plus + Vite | 组件化开发、构建高效 |
| 移动学习端 | 微信小程序原生（WXML/WXSS/JS） | 免安装、跨平台，贴合一线自主学习 |
| 报表导出 | EasyExcel | 培训记录与统计报表导出 |

### 4.3 关键技术问题

**（1）标准闭环的信息系统落地**：将指南的「范围—需求—内容—计划—实施—评估—总结」抽象为可流转的业务实体与状态机，明确计划审批、任务下发、考核判定、档案归集的衔接关系，并保证各环节均有记录留存。

**（2）一套后端支撑三端的接口契约统一**：学员端 Web 与小程序共用同一套学员接口，统一返回结构、鉴权方式与时间格式，避免重复开发。

**（3）小程序端学习进度记录与续传**：按固定间隔、暂停、页面卸载时上报进度；再次进入时按已上报进度续播；上报失败静默重试并写入本地缓存，降低弱网下的进度丢失风险。

**（4）审批链路与数据隔离**：落实「培训计划经负责人审核批准」与「部门负责人确认本部门需求」的职责要求；在服务层依据登录态强制隔离学员数据，不接受前端传入的用户标识，并对「提交人审核自身内容」等违规情形加以拦截。

**（5）考核环节防作弊**：答题阶段接口不向客户端返回正确答案，仅在成绩查询时返回答案解析，从接口层降低通过抓包获取答案的风险，保障培训结果评估的真实性。

## 五、可行性分析

### 5.1 技术可行性

所选技术栈均为成熟开源方案，文档完备；微信小程序官方框架与开发者工具成熟；小程序与后端通过标准 HTTP + JSON 交互，与 Web 端一致，无需专有中间件。

### 5.2 经济可行性

全部组件均为开源软件，无授权费用；小程序免分发、免上架，推广与运维成本低；可部署于单台常规云主机，硬件成本可控。

### 5.3 操作与合规可行性

管理端采用表格/表单的常规交互；小程序端操作直观、扫码即可使用。系统功能按 GMP 指南培训管理要素与流程组织，有助于企业规范培训管理、保存培训记录，契合 GMP 检查对培训留痕的要求。
